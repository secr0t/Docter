# 🩺 Doctor

> **像看医生一样，诱出你自己都没意识到的真实问题。**

Doctor 是一个面向 **问题发现、问题定义与根因诊断** 的 AI Skill。

它不会在看到一个现象后立即给出结论，而是通过持续追问、建立假设、收集证据和排除其他可能，逐步判断：

**到底出了什么问题、用户真正想解决什么，以及为什么会出现这个问题。**

------

## ✨ 核心理念

Doctor 的核心不是“给答案”，而是：

> **在回答之前，先确保我们回答的是正确的问题。**

它主要处理两类问题：

| 模式 | 目标 |
| --- | --- |
| 🧭 GUIDANCE | 从模糊方向中收敛出真实目标 |
| 🩺 DIAGNOSIS | 从现象中判断真正的问题与根因 |

Doctor 的生命周期非常简单：

~~~text
用户的问题
   ↓
🩺 Doctor
   ↓
问题定义 / 诊断
   ↓
用户确认
   ↓
DOCTOR_DONE
~~~

**到这里 Doctor 就完成了。**

Doctor 不负责：

~~~text
❌ 怎么解决
❌ 技术方案
❌ 代码修改
❌ 实施方案
❌ Remediation Plan
~~~

------

## 🧠 为什么需要 Doctor？

现实中的用户经常并不知道自己真正的问题是什么。

例如：

> “我们的 SOC 告警很多，但是感觉效果不好。”

这句话并没有真正定义问题。

Doctor 不会马上回答“怎么优化 SOC”，而会继续追问：

- 你说的“效果不好”具体指什么？
- 是发现率低、误报高、响应慢，还是无法证明覆盖能力？
- 你现在希望得到的是问题诊断、建设方向，还是一份评估框架？

最终可能发现，真正的问题其实是：

> **你无法证明 SOC 对关键攻击场景具备有效的检测与响应能力。**

这时 Doctor 才算完成任务。

## 🔨 Doctor 与 Grill-me

**Grill-me 不是 Doctor 的下一阶段。**

两者解决的是不同问题：

| | 🩺 Doctor | 🔨 Grill-me |
| --- | --- | --- |
| 核心问题 | **我到底要解决什么问题？** | **我现在这个想法经不经得起推敲？** |
| 核心任务 | 问题发现、需求收敛、根因诊断 | 挑战假设、判断、方案与决策 |
| 何时使用 | 问题本身还不清楚 | 用户已经有明确的想法、判断或方案 |
| 输出 | Problem Definition / Diagnosis | Stress-tested Thinking |
| 是否强制衔接 | **否** | **否** |

不存在固定的 Doctor → Grill-me 流水线。

~~~text
                用户
                  │
          ┌───────┴───────┐
          ↓               ↓
      🩺 Doctor        🔨 Grill-me
     把问题问对         把想法想透
          │               │
          ↓               ↓
   Problem Definition   Stress-tested
      / Diagnosis         Thinking
~~~

用户可以：

- 只使用 Doctor；
- 只使用 Grill-me；
- 先使用 Doctor，再主动使用 Grill-me；
- 直接继续普通对话。

**两者可以协作，但不存在隶属关系。**

------

## 🎯 Doctor 负责什么？

Doctor 主要负责：

- 识别用户描述中的真实问题
- 区分事实、推测和结论
- 建立多个可能的问题假设
- 通过高价值问题获取关键信息
- 收集能够证明或否定假设的证据
- 比较不同诊断之间的可能性
- 排除不成立的解释
- 深入分析问题的根因
- 在需求型问题中收敛真实目标
- 最终形成明确、可确认的问题定义

Doctor **不负责解决问题**。
